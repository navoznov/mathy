# Mathy — тренажёр устного счёта

**Дата:** 2026-09-01
**Статус:** дизайн утверждён, готов к планированию реализации

## Задача

Ребёнок 9 лет испытывает трудности с устным счётом. Нужно приложение, которое
одновременно **тренирует** навык и **диагностирует** конкретные пробелы, чтобы
родитель видел не общую оценку, а что именно не работает.

Ключевое отличие от простого генератора примеров: приложение хранит и
агрегирует данные по каждому решённому примеру, а не только итог сессии.

### Критерии успеха

1. Ребёнок может пройти сессию от начала до конца без помощи взрослого.
2. После сессии родитель видит: сколько ошибок, где именно, что решается медленно.
3. Родитель может за минуту перенастроить сложность под текущую задачу
   («сегодня только таблица на 7 и 8»).
4. Данные накапливаются между сессиями и показывают динамику.

### Вне области

PWA и офлайн-режим, несколько профилей детей, звуки, синхронизация между
устройствами, серверная часть, авторизация. Каждое добавляет поверхность для
багов и не требуется для достижения критериев выше.

## Стек

- **TypeScript** — нетривиальные структуры данных (настройки, сессии, агрегаты);
  типы ловят ошибки до запуска, стоимость нулевая (Vite компилирует TS из коробки).
- **React** — реальное состояние: текущий пример, ввод, таймеры, фаза сессии,
  модалка, история. Ручная синхронизация DOM — источник багов. Размер бандла
  для домашнего приложения не значим.
- **Vite** — сборка, dev-сервер, `base` для GitHub Pages.
- **Vitest** — тесты доменного слоя.
- **Хеш-роутинг собственной реализации** (~15 строк на `hashchange`).
  GitHub Pages не даёт history-fallback без костыля с `404.html`;
  библиотека роутинга на два экрана — оверкилл.
- **Хостинг:** GitHub Pages, деплой через GitHub Actions.

## Архитектура

Вся логика вынесена из React в чистые функции. Доменный слой не знает про DOM
и тестируется без него.

```
src/
  domain/
    types.ts        Op, OpConfig, Settings, Task, Attempt, Session, Summary
    generator.ts    generateTasks(settings) -> Task[]
    scoring.ts      checkAnswer, calcStars, summarize
    analytics.ts    byOperation, multiplicationGrid, topProblems
  storage/
    safeStorage.ts  обёртка над localStorage с try/catch
    settings.ts     load / save / DEFAULTS / PRESETS / миграции
    history.ts      append / list / clear / export, кап 200 сессий
  ui/
    App.tsx         хеш-роутинг: '' | '#/admin'
    practice/       PracticeScreen, TaskCard, Keypad, ResultModal
    admin/          AdminScreen, PinGate, SettingsForm,
                    WeakSpots, MultiplicationHeatmap, HistoryTable
  main.tsx
```

Границы: `ui/` зависит от `domain/` и `storage/`; `storage/` зависит от
`domain/types`; `domain/` не зависит ни от чего. Любой модуль домена можно
понять и протестировать в отрыве от остальных.

## Модель данных

```ts
type Op = 'add' | 'sub' | 'mul' | 'div';

interface OpConfig {
  enabled: boolean;
  aMin: number; aMax: number;   // для div: диапазон частного (ответа)
  bMin: number; bMax: number;   // для div: диапазон делителя
}

interface Settings {
  version: 1;                   // ключ миграции схемы
  taskCount: number;            // 5..50
  ops: Record<Op, OpConfig>;
  requireCarry: boolean;        // сложение только с переходом через десяток
  allowNegative: boolean;       // вычитание может уходить в минус
  instantFeedback: boolean;     // true = тренировка, false = контрольная
  adminPin: string | null;
}

interface Task {
  op: Op; a: number; b: number; expected: number;
}

interface Attempt {
  op: Op; a: number; b: number;
  expected: number;
  given: number;
  correct: boolean;
  ms: number;                   // время именно на этот пример
}

interface Session {
  id: string;                   // ISO-timestamp, он же ключ сортировки
  startedAt: number;            // epoch ms
  totalMs: number;              // сумма attempt.ms
  plannedCount: number;         // сколько примеров было сгенерировано
  aborted: boolean;             // сессия прервана, не доведена до конца
  attempts: Attempt[];          // только фактически отвеченные примеры
  stars: number;
}

interface Summary {
  total: number;
  correct: number;
  wrong: number;
  errorRate: number;            // 0..1
  stars: number;
  totalMs: number;
  avgMs: number;
  slowest: Attempt | null;
  mistakes: Attempt[];
}
```

### Хранение

Два ключа в localStorage: `mathy.settings` и `mathy.history`.
Сериализация — обычный `JSON.stringify` без отступов.

Кортежный формат (`[op,a,b,given,ms]`) рассматривался и отклонён: экономит
примерно вдвое, но 200 сессий по 20 примеров занимают ~300 КБ при лимите 5 МБ.
Экономия 6% квоты не стоит потери читаемости и кода сериализации.

История ограничена 200 последними сессиями (при добавлении 201-й самая старая
удаляется). В админке есть экспорт всей истории в JSON-файл и полная очистка.

`safeStorage` оборачивает все обращения в `try/catch`. Приватный режим,
переполнение квоты и битый JSON — реальные сценарии; в каждом из них
приложение продолжает работать (теряя только сохранение), а не падает
в белый экран.

Миграции: при чтении настроек сравнивается поле `version`. Несовпадение или
отсутствие — настройки заменяются на `DEFAULTS`. Записи истории при смене
версии не удаляются: неизвестные поля игнорируются, отсутствующие получают
значения по умолчанию.

## Генератор примеров

`generateTasks(settings): Task[]` — единственная точка генерации.

**Распределение операций.** Включённые операции распределяются по количеству
примеров поровну (остаток раздаётся первым по порядку), затем массив
перемешивается. Независимый `random()` на каждом шаге регулярно даёт перекос
(11 сложений и 2 умножения на 15 примеров), из-за чего тренировка перестаёт
соответствовать настройкам.

**Правила по операциям:**

| Операция | Генерация |
|---|---|
| `add` | `a ∈ [aMin,aMax]`, `b ∈ [bMin,bMax]`. При `requireCarry` требуется `a % 10 + b % 10 >= 10` |
| `sub` | `a ∈ [aMin,aMax]`, затем `b ∈ [bMin, min(bMax, a)]` при `allowNegative: false`; иначе `b ∈ [bMin,bMax]` |
| `mul` | `a ∈ [aMin,aMax]`, `b ∈ [bMin,bMax]` |
| `div` | делитель `b ∈ [bMin,bMax]`, частное `q ∈ [aMin,aMax]`, задача `(b·q) ÷ b`. Всегда нацело |

Вычитание и деление генерируются от результата, а не отбором сгенерированных
пар. Это исключает ретраи и делает генерацию за один проход.

**Дубли.** Rejection sampling с лимитом в 50 попыток на пример: повторно
выпавшая пара `(op,a,b)` перегенерируется. При исчерпании лимита повтор
допускается, но никогда не подряд с предыдущим примером.

**Вырожденные настройки.** «Умножение 2..3 × 2..3» даёт 4 уникальных примера
при запрошенных 15. Генератор не зацикливается (лимит попыток), а
`SettingsForm` при сохранении показывает предупреждение с числом доступных
уникальных примеров.

**Невозможные настройки.** Если ни одна операция не включена, `taskCount < 1`
или диапазон вывернут (`aMin > aMax`), генератор бросает ошибку. Форма
настроек не даёт сохранить такую конфигурацию, кнопка «Начать» на стартовом
экране блокируется с пояснением.

## Подсчёт результата

```ts
calcStars(summary: { wrong: number }): number   // max(0, 5 - wrong)
```

Формула вынесена в отдельную чистую функцию с тестами на границах.
Известное ограничение: она не учитывает объём — 3 ошибки из 5 и 3 ошибки
из 30 дают одинаковые 2 звезды, хотя это принципиально разный результат.
Формула принята как временная по решению заказчика; изоляция в одной
функции делает замену правкой в несколько строк.

**Прерванная сессия всегда получает 0 звёзд**, независимо от числа ошибок.
Иначе появляется тривиальная лазейка: начать, не ответить ни разу, прервать —
и получить максимальные 5 звёзд за ноль работы.

`checkAnswer` сравнивает целые числа. Пустой ввод невозможен: кнопка
подтверждения заблокирована, пока поле пустое.

## Замер времени

`performance.now()` фиксируется при показе примера и при подтверждении ответа;
разность пишется в `attempt.ms`. `totalMs` сессии — сумма времён примеров,
а не wall-clock от старта до финиша: перерыв посреди сессии не должен искажать
статистику. `avgMs = totalMs / total`.

## Экраны

### Стартовый (`#/`)

Крупная кнопка «Начать». Под ней строка текущих настроек («15 примеров: + − ×»).
Внизу три последних результата (дата и звёзды) и неприметная ссылка «Настройки».

### Решение

Прогресс «Пример 3 из 15» с полосой, крупный пример, поле ввода, экранная
цифровая клавиатура (Keypad). Физическая клавиатура и Keypad работают
параллельно: Enter эквивалентен кнопке «Дальше →». Кнопка неактивна при
пустом поле.

Кнопки «Пропустить» нет сознательно: пропускаться будут именно трудные примеры,
то есть ровно те, ради которых приложение написано.

Кнопка «Прервать» с подтверждением. Прерванная сессия **пишется в историю**
с `aborted: true`: уже отвеченные примеры — это настоящие данные о ребёнке,
и терять их незачем. `plannedCount` хранит, сколько примеров было выдано,
чтобы в истории читалось «прервана на 4 из 15». Исключение — сессия без единого
ответа: писать её незачем, это просто случайное нажатие «Начать».

**Обратная связь** зависит от `instantFeedback`:
- `true` (тренировка, значение по умолчанию) — после ответа на 800 мс
  показывается результат: зелёная отметка либо красная с правильным ответом,
  затем автопереход к следующему примеру.
- `false` (контрольная) — переход сразу, результат только в конце.

Немедленная обратная связь — наиболее сильный фактор в тренировке навыка;
контрольный режим существует для чистого измерения без подсказок.

### Модалка результата

Показывается и для завершённой, и для прерванной сессии. У прерванной вместо
звёзд стоит пометка «Прервано, 4 из 15», остальная статистика считается
по фактически отвеченным примерам.

Звёзды, затем цифры: всего примеров, правильных (N и %), ошибок (N и %),
общее время, среднее время на пример. Ниже — разбор каждой ошибки строкой
`7 × 8 = 54, правильно 56` и отдельно самый долгий пример.
Кнопки «Ещё раз» и «На главную».

### Админка (`#/admin`)

**PinGate.** Если `adminPin` задан, вход требует 4-значный код. Разблокировка
запоминается в `sessionStorage` до закрытия вкладки. Это не безопасность —
код лежит на клиенте — а барьер от соблазна: иначе первым действием ребёнка
станет «Легко, 3 примера, только сложение».

**SettingsForm.** Сверху три кнопки-пресета (Легко / Средне / Сложно),
заполняющие все поля одним кликом. Ниже раскрывающийся блок тонкой настройки:
количество примеров, чекбокс и пара диапазонов на каждую операцию, флаги
`requireCarry` и `allowNegative`, переключатель режима обратной связи,
установка и сброс PIN. Для деления поля подписаны явно («частное», «делитель»).

**WeakSpots** — сводка по операциям: точность и среднее время отдельно
по `+ − × ÷` за всю историю. Попытки из прерванных сессий учитываются
наравне с остальными: ребёнок эти примеры действительно решал.

**MultiplicationHeatmap** — сетка 2..10 × 2..10, каждая ячейка окрашена по
накопленной точности (≥90% / 70–89% / <70% / нет данных). Ячейка учитывает обе
перестановки множителей и примеры на деление, сводимые к той же паре. Это
основной диагностический инструмент: провальные строки видны за секунды.

**Топ проблемных** — 10 примеров с наибольшей долей ошибок и 10 самых
медленных по среднему времени.

**HistoryTable** — список сессий (дата, время, число примеров, ошибки, звёзды,
общее время), клик раскрывает список попыток. Прерванные сессии помечены
и показывают «4 из 15» вместо числа примеров. Кнопки экспорта в JSON и очистки
истории (с подтверждением).

## Тестирование

Тестируется доменный слой и storage. UI-тесты не пишутся: для приложения
такого объёма это плохой обмен времени на пользу.

**generator**
- сгенерированные операнды лежат в заданных диапазонах;
- деление всегда даёт целый результат;
- при `allowNegative: false` вычитание не даёт отрицательных;
- при `requireCarry` каждое сложение действительно с переходом;
- операции распределены поровну между включёнными;
- нет двух одинаковых примеров подряд;
- вырожденные настройки (4 возможных примера, запрошено 15) завершаются
  за конечное время;
- невозможные настройки бросают ошибку.

**scoring**
- `calcStars`: 0 ошибок → 5, 5 ошибок → 0, 7 ошибок → 0 (не уходит в минус);
- `summarize`: проценты, среднее время, поиск самого долгого примера;
- прерванная сессия даёт 0 звёзд даже при нуле ошибок;
- прерванная сессия без единого ответа в историю не пишется;
- сессия с нулём примеров не даёт `NaN`.

**storage**
- несовпадение `version` откатывает настройки к `DEFAULTS`;
- битый JSON в localStorage не роняет загрузку;
- недоступный localStorage не роняет приложение;
- история обрезается до 200 записей.

**analytics**
- агрегация по операциям;
- ячейка тепловой карты учитывает обе перестановки множителей и деление;
- пустая история даёт корректный пустой агрегат;
- попытки из прерванных сессий попадают в агрегаты.

## Деплой

GitHub Actions на push в `main`: `npm ci` → `npm test` → `npm run build` →
`actions/deploy-pages`. Падение тестов блокирует деплой.

В `vite.config.ts` обязателен `base: '/mathy/'` (имя репозитория). Без этого
на GitHub Pages ломаются все пути к ассетам — самая частая ошибка при таком
деплое. Хеш-роутинг работает с одним `index.html` без дополнительной настройки.
