# Деление с остатком

**Дата:** 2026-09-24
**Статус:** дизайн утверждён, готов к планированию реализации

## Задача

Ребёнок проходит в школе деление с остатком. Деление в тренажёре уже есть, но только нацело:
пример собирается из делителя и частного, делимое = делитель × частное. Нужен режим, в котором
делимое не обязательно делится нацело, а ответ состоит из двух чисел — частного и остатка.

### Критерии успеха

1. Родитель одной галочкой включает деление с остатком, не перенастраивая диапазоны.
2. Ребёнок вводит частное и остаток на одном экране так, как пишет в тетради: `17 ÷ 5 = 3 ост. 2`.
3. Ошибка в любом из двух чисел видна в разборе, итогах и истории.
4. Старые настройки и история читаются без потерь.

### Вне области

- Отдельная операция «деление с остатком» рядом с обычным делением (смешивание обоих форматов
  в одной сессии). Не окупает пятого значения `Op`, которое протекло бы в историю, аналитику
  и пресеты.
- Галочки по разрядности делимого и делителя («однозначное / двузначное»). Они дублируют
  диапазоны с меньшей точностью и конфликтуют с ними.
- Отдельная аналитика по остаткам («путает остаток», «не замечает нулевой остаток»).
- Включение флага в пресеты.
- Частичный зачёт за верное частное при неверном остатке.

## Настройки

`Settings` получает флаг `divRemainder: boolean`, по умолчанию `false` во всех трёх пресетах.
`version` не бампается: `loadSettings` доливает недостающее поле из `DEFAULTS`, старые настройки
получают `false`. Пресет, как и сейчас, перезаписывает флаг (это уровень сложности, а не
родительское решение вроде кода или доступности тренировки).

Форма: галочка «С остатком» внутри блока деления, видна только при включённом делении.
Подпись под диапазонами зависит от флага:

- выключен — «Пример собирается из делителя и частного — деление всегда нацело.» (как сейчас);
- включён — «Остаток от 0 до делитель − 1, иногда выпадает 0.»

Диапазоны остаются прежними: «Частное (ответ)» и «Делитель».

## Генератор

При `divRemainder === false` поведение и последовательность вызовов `rng` не меняются —
выдача с тем же `rng` совпадает со старой.

При `divRemainder === true`:

```
b = randInt(bMin, bMax)     // делитель
q = randInt(aMin, aMax)     // частное
r = randInt(0, b − 1)       // остаток
Task { op: 'div', a: b·q + r, b, expected: q, remainder: r }
```

Остаток 0 выпадает с вероятностью 1/b и остаётся в формате «с остатком» (`18 ÷ 6 = 3 ост. 0`):
ребёнок учится замечать, что поделилось нацело. Валидация не меняется: `bMin ≥ 1` уже
проверяется, при `b = 1` остаток всегда 0 — корректный пример.

Дедупликация по `op:a:b` работает без изменений: разный остаток даёт разное делимое,
а пара (a, b) однозначно определяет q и r.

`uniqueTaskSpace` для деления при включённом флаге: `spanA × Σ b` по `b ∈ [bMin, bMax]`
(у делителя `b` ровно `b` вариантов остатка). Без флага — как сейчас.

## Модель

```ts
interface Task {
  // ...
  /** Есть только у деления с остатком; 0 — поделилось нацело, но ответ в формате «ост.». */
  remainder?: number;
}

interface Attempt {
  // ...
  /** Есть только у деления с остатком. */
  expectedRemainder?: number;
  givenRemainder?: number;
}
```

Признак «пример с остатком» — наличие поля (`task.remainder !== undefined`), а не его значение.

**Проверка ответа.** `checkAnswer(task, given, givenRemainder?)`: для задачи с `remainder` верно,
только если совпали и частное, и остаток. Для остальных задач — как сейчас.

**Звёзды** не меняются: одна неверная попытка — одна ошибка.

**История.** `normalize` в `history.ts` не валидирует попытки внутри сессии — массив
передаётся как есть. Старые записи просто не содержат полей остатка и отображаются как обычные.
Валидацию попыток в рамках этой задачи не добавляем.

## Аналитика

- Тепловая карта уже кладёт деление в ячейку `[делитель, частное]`: `17 ÷ 5 = 3 ост. 2` попадёт
  в ячейку `5 × 3`. Это намеренно — проверяется то же знание таблицы умножения. Кода не меняем.
- `topProblems` группирует по `op:a:b` — деление с остатком группируется корректно.
  `WeakSpots` показывает только сам пример, без ответа, — изменений не требует.

## Экран решения

**Карточка** (`TaskCard`). Если у задачи есть `remainder`: `17 ÷ 5 = [ ] ост. [ ]`, активное
поле подсвечено. Иначе — как сейчас.

**Состояние ввода** (`PracticeScreen`). Для задачи с остатком ввод — две строки (частное,
остаток) и индекс активного поля. Для остальных задач — одно поле, как сейчас.

**Клавиатура** (`Keypad`). Необязательный проп: вместо `±` клавиша «ост.», переводящая курсор
в поле остатка. Для остальных задач клавиатура прежняя.

**Управление:**

| Действие | Поле частного | Поле остатка |
|---|---|---|
| Enter / «Дальше» | при непустом частном — перейти в остаток | при заполненных обоих полях — отправить |
| «ост.» | перейти в остаток | — |
| `⌫` | стереть символ | стереть символ; в пустом поле — вернуться в частное |
| Тап по полю | активировать это поле | активировать это поле |
| `-` с клавиатуры | игнорируется | игнорируется |

Отправка возможна только при заполненных обоих полях: ноль в остатке вводится явно.
Кнопка «Дальше» активна, когда нажатие что-то сделает (переход или отправка).

## Отображение ответа

Форматирование ответа — одна функция в `src/ui/format.ts` (`3` или `3 ост. 2`). Ею пользуются:

- разбор ошибки в тренировке: `❌ 3 ост. 1`, ниже `17 ÷ 5 = 3 ост. 2`;
- `formatAttempt` — итоги (`ResultModal`) и история (`HistoryTable`):
  `17 ÷ 5 = 3 ост. 1, правильно 3 ост. 2`.

## Тестирование

Только `src/domain/**` и `src/storage/**`, UI-тесты не пишутся (правило проекта).

- **Генератор**
  - при включённом флаге: всегда `a = b·q + r`, `0 ≤ r < b`, `q` и `b` в диапазонах;
  - с фиксированным `rng` выпадают и `r = 0`, и `r > 0`;
  - при выключенном флаге: выдача с тем же `rng` совпадает с прежней, поля `remainder` нет;
  - `uniqueTaskSpace` учитывает остатки.
- **`checkAnswer`**: верно только при совпадении обоих чисел; неверный остаток при верном
  частном — ошибка; для задач без остатка поведение прежнее.
- **`loadSettings`**: старые настройки без `divRemainder` получают `false`, диапазоны сохраняются.
- **Пресеты**: у всех `divRemainder === false`.
