# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Mathy — тренажёр устного счёта для ребёнка. SPA без бэкенда: React 19 + TypeScript + Vite,
всё состояние в `localStorage`, хостинг на GitHub Pages.

## Команды

```bash
npm run dev                              # локальный сервер
npm test                                 # vitest run, весь домен + storage
npx vitest run src/domain/scoring.test.ts  # один файл
npx vitest run -t 'фрагмент имени'         # один тест по имени
npm run lint                             # oxlint
npm run build                            # tsc -b && vite build → dist/
```

**Нужен Node 20.19+ или 22.12+.** На старых версиях npm молча пропускает платформенный
биндинг сборщика, и `npm test` падает с невнятным «Cannot find native binding».

## Архитектура

Три слоя, зависимости строго в одну сторону: `ui → storage → domain`.

- **`src/domain/**`** — чистая логика, не импортирует ничего из `ui` и `storage`.
  `types.ts` (модель), `generator.ts` (составление примеров), `scoring.ts` (звёзды и сводка),
  `analytics.ts` (агрегаты по истории).
- **`src/storage/**`** — сериализация в Web Storage, импортирует только `domain/types`.
- **`src/ui/**`** — React. Роутинг хешевый и самодельный (`useHashRoute`), библиотеки роутера нет:
  `#/admin` → админка, всё остальное → тренажёр.

Поток прохождения — машина фаз в `PracticeFlow.tsx`: `idle → running → done`.
`PracticeScreen` держит попытки в `useRef` и меряет время через `performance.now()`
на каждый пример отдельно; `Session.totalMs` — сумма `attempt.ms`, а не wall-clock.

Сессия идёт в одном из режимов `PracticeMode` — `training` (правильность видна сразу:
похвала уезжает по таймеру, разбор ошибки ждёт нажатия) или `exam` (молча, всё в итогах).
Режим выбирается при старте, едет через фазу `running` и **сохраняется в `Session.mode`** —
это свойство прохождения, а не настройка, в `Settings` его нет.

### Инварианты, которые легко нарушить

- **Детерминизм.** Любая функция с генерацией или перемешиванием принимает
  `rng: () => number = Math.random` последним параметром. Тесты передают свой rng.
- **Только `safeStorage`.** Прямые вызовы `localStorage.*` / `sessionStorage.*` вне
  `src/storage/safeStorage.ts` запрещены (в тестах — можно, там это фикстуры). Все обёртки
  глотают исключения и возвращают `null`/`false`: браузер может блокировать хранилище,
  приложение обязано это пережить, а UI — показать предупреждение, а не упасть.
- **Формула звёзд живёт только в `calcStars`.** Числа `5` в контексте звёзд больше нигде быть не должно.
- **Для отображения используйте `summarize(session)`, а не `session.stars`.** Поле в записи —
  историческое значение на момент сессии, правило начисления может смениться.
- **Символы операций — конкретные кодовые точки**: `−` U+2212 (не дефис), `×` U+00D7, `÷` U+00F7.
  Берите из `OP_SYMBOL`, не набивайте руками.
- **`base: '/mathy/'` в `vite.config.ts`** обязан совпадать с именем репозитория, иначе на Pages
  не грузятся ассеты.
- **Обновляющие функции `setState` должны быть чистыми.** Побочный эффект внутри них в StrictMode
  выполнится дважды — сессия запишется в историю два раза.

### Хранилище

Ключи `mathy.settings` и `mathy.history`. `Settings.version` = `1`; при несовпадении версии или
битом JSON настройки молча откатываются к `DEFAULTS`, а не роняют загрузку. История ограничена
`HISTORY_CAP` = 200 последними сессиями, записи нормализуются при чтении (неизвестные поля
игнорируются, битые — отбрасываются). Сессия без единого ответа в историю не пишется.

Модель `Session` развивается через `normalize` в `history.ts`, а не через версионирование:
новое поле получает разумное значение для старых записей (так `mode` у сессий до появления
режимов становится `training`). Версия есть только у `Settings`.

Код от настроек (`adminPin`) хранится открытым текстом — это барьер от соблазна заглянуть,
а не защита. Не пытайтесь «усилить» его хешированием: угрозы, от которой это спасает, здесь нет.

### Неочевидное в аналитике

- Тепловая карта сводит деление к умножению: `56 ÷ 8 = 7` попадает в ту же ячейку, что `7 × 8`,
  и перестановки множителей объединяются.
- `topProblems` ранжирует по **абсолютному числу ошибок**, а не по доле. Сложение и вычитание
  почти не повторяются (`total: 1`), поэтому единственный промах даёт `errorRate` 1.0 и забивает
  топ случайностями. Не «чините» это на сортировку по доле.
- Попытки из прерванных сессий учитываются в агрегатах наравне: ребёнок их действительно решал.

## Тестирование

Тестируется `src/domain/**` и `src/storage/**`. **UI-тесты не пишутся** — сознательное решение
по спеке, не пробел.

Окружение vitest — `node`, а не jsdom: DOM не нужен, а jsdom не запускается на Node 22.11.
`localStorage`/`sessionStorage` подставляет полифил из `src/test/storage-polyfill.ts`, который
кладёт в `globalThis` настоящий класс `Storage` — тесты подменяют `Storage.prototype.getItem`,
чтобы проверить поведение при недоступном хранилище.

## Проектные документы

`docs/superpowers/specs/` и `docs/superpowers/plans/` — исходные спека и план реализации.
Полезны как объяснение «почему так», но **код авторитетнее**: план местами разошёлся с реализацией
(например, описывает ключ `mathy.admin-unlocked` в sessionStorage и функции `readTemp`/`writeTemp`,
которых нет — разблокировка админки живёт в обычном `useState` в `PinGate`). Сверяйтесь с кодом.
